# Cute labels

Cute labels announce significance instead of stating the useful point. Remove
the label and state the finding directly.

| Before | After |
| --- | --- |
| **My take:** current state is acceptable, not ideal. <sup>1</sup> | The current state is acceptable but not ideal. |
| **The intent, honestly stated:** this is a launch hero for devs who run several AI agents at once. <sup>2</sup> | This launch hero is for developers who run several AI agents at once. |
| **The catch this hour:** running the hub proved that the sweep never indexes at its production budget. <sup>3</sup> | Running the hub showed that the sweep never indexes anything within its production work budget. |
| **The bit that matters:** test on a real iPhone, on cellular with Wi-Fi off. <sup>4</sup> | Test on a real iPhone over cellular with Wi-Fi off. |
| **Accuracy catch worth having:** the proposed "history stays on your own machine" copy is false with a remote hub. <sup>5</sup> | The proposed "history stays on your own machine" copy is false when the hub is remote. |
| **Real contradiction found:** one rule says the pair commits on the first non-attention event, while another says a busy event never closes a pair. <sup>6</sup> | The two rules contradict each other. |
| **One real miss:** I reported the work as done despite a Swift 6 `Sendable` error. <sup>7</sup> | I reported the work as done despite a Swift 6 `Sendable` error. |
| **The hole.** `ci.yml` has no iOS job. <sup>8</sup> | `ci.yml` has no iOS job. |
| **One migration gotcha.** The build number comes from `testflight.yml`'s run counter. Moving the job to `deploy.yml` could lower the next build number. <sup>9</sup> | Moving the job to `deploy.yml` changes the workflow run counter, so the next build number could be lower. |
| **The deeper mechanism:** both the hub and forwarder filter live frames using `seq <= since`. <sup>10</sup> | Both the hub and forwarder filter live frames using `seq <= since`. |
